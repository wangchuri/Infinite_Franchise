# 灵感 · 世界观冷启动助手（材料 → Agent → 草稿）

> 类型：`world`（创建流程 / Agent / Wiki 样式）  
> 日期：2026-07-10  
> 状态：灵感草案，待并入正式设计  
> 来源：产品讨论  
> 相关：`world-入口Wiki写作-2026-07-09.md` · 现有编辑器 `homepageConfig` · `/worlds`

---

## 1. 问题

小白手里往往只有：

- 自己写过的小文档  
- 灵感片段、角色草稿、设定笔记  

现有路径是「空白创建 → 空编辑器」，不知道从哪填、填多少才算能发布。  
需要一条 **不挡老手、专帮冷启动** 的旁路。

---

## 2. 核心想法

> **丢材料进来 → Agent 读内容并给出结构化建议 → 人确认 → 生成草稿世界（含 Wiki 样式）→ 进现有编辑器精修**

原则：

1. **主路径不变**：会建世界的人仍可「空白创建」。  
2. **Agent 不静默写库**：词条、样式都必须人点确认（采纳 / 编辑 / 丢弃）。  
3. **自动化只负责冷启动**；精修仍在 `/worlds/[id]/edit`。

---

## 3. 入口

在 **创建 / 我的世界观** 页（`/worlds`）上方增加次要入口，例如：

> **不知道该从哪创建？**

- 主按钮仍是「再开一个新世界」等空白创建  
- 点次要入口 → 进入助手对话页（建议路由：`/worlds/assist`）

---

## 4. 助手界面（对话 + 拖材料）

```
┌──────────────────┬────────────────────────────┬──────────────────┐
│ 材料             │  与 Agent 对话               │ 待确认建议        │
│                  │                            │                  │
│ [拖入 / 粘贴]     │  气泡：读完了，气质偏雾港…    │ ☐ 世界简介       │
│ · 笔记A.md       │  用户：再冷一点               │ ☐ 人物 · 守夜人  │
│ · 灵感片段.txt   │  Agent：已把强调色调冷…       │ ☐ 地点 · …       │
│                  │                            │ ☐ Wiki 样式方案  │
│                  │                            │ [生成草稿世界]    │
└──────────────────┴────────────────────────────┴──────────────────┘
```

### 4.1 材料区

- 拖入或选择文件：优先 `.md` / `.txt`（可多份）  
- 也可大框粘贴纯文本  
- 列表可移除单份材料；Agent 以当前材料集合为上下文

### 4.2 对话区

- 用户可补充意图：「偏科幻」「先只要人物和简介」  
- Agent 说明自己读到了什么、建议了什么（可追问改样式 / 改词条）

### 4.3 建议区（结构化卡片）

每条可：**采纳 / 编辑 / 丢弃**。  
全部（或所选）确认后 → **生成草稿世界** → 跳转编辑器。

---

## 5. Agent 职责

### 5.1 读

用户拖入 / 粘贴的文本（及可选的一句话气质、标签）。

### 5.2 产出（建议，非直接落库）

| 块 | 内容 |
|----|------|
| 元信息 | 建议世界名、一句话简介、标签候选 |
| Wiki 词条 | 人物 / 地点 / 物品 / 概念等：标题 + 短摘要（+ 可选正文草稿） |
| 时间线 | 可选事件节点（名称 / 纪年 / 一句说明） |
| **Wiki 界面样式** | 见 §6，写入 `homepageConfig` 方案 |

### 5.3 不做

- 不未经确认创建正式世界或覆盖已有世界  
- 不代替用户做最终审美决定（样式可预览、可改）

---

## 6. Agent 编排 Wiki 界面样式

与现有 `homepageConfig` 对齐（见前端 `lib/homepage-config.ts` / 编辑器 StylePanel）：

| 字段 | Agent 可建议 |
|------|----------------|
| `theme` | `paper` / `ink` / `mist` / `ember`（按文风推断） |
| `layout` | `classic` / `sidebar` / `magazine` |
| `accent` | 强调色（海雾、砂暖、墨色等） |
| `modules` | 开哪些模块、建议顺序（介绍 / 人物 / 物品 / 时间轴…） |
| `showTags` | 是否展示标签 |
| `heroStyle` | `banner` / `compact` / `none` |

对话中可继续改，例如：「再冷一点」「时间轴放上面」「先别显示物品」。  
建议区展示 **样式方案卡片 + 简易预览**；确认后与词条一并写入草稿。

无材料或文风不明时：给稳妥默认（如 `paper` + `classic`），不强行花哨。

---

## 7. 落库时机

用户点「生成草稿世界」且至少确认了必要项（如名称 + 简介，或名称 + 若干词条）之后：

1. `POST /api/worlds` 建草稿（或专用 `POST /api/worlds/from-assist`）  
2. 写入已采纳的 `wiki_entries` / 时间轴  
3. `PATCH` `homepageConfig` 为已确认的样式方案  
4. 跳转 `/worlds/{id}/edit`

---

## 8. 实现分档（务实）

| 档 | 能力 | 说明 |
|----|------|------|
| A | 对话壳 + 拖材料 + 规则拆分（标题/空行/简单实体） | 无模型也能演示流程 |
| B | 接大模型：简介、词条、**样式方案** | 体验质变 |
| C | 多轮追问补缺、预览 Wiki 再确认 | 后续增强 |

建议：先定 **入口 + 界面 + Agent 输入输出 JSON（含 homepageConfig）**，A/B 可替换同一契约。

### 8.1 Agent 输入输出（草案）

**输入**

```text
materials: [{ name, text }, ...]
userMessage?: string
hints?: { tone?, tags? }
```

**输出**

```text
assistantMessage: string
proposal: {
  name?, description?, tags?,
  entries?: [{ category, title, summary, content? }],
  timeline?: [{ title, eventDate?, description? }],
  homepageConfig?: { theme, layout, accent, modules, showTags, heroStyle }
}
```

| 文档 / 实现 | 关系 |
