## 1. 产品概述

### 1.1 产品名称

- **中文名**：无限企划
- **英文名**：Infinite Franchise
- **包名**：`com.ximocy.InfiniteFranchise`

### 1.2 一句话描述

一个以「世界观」为容器的创作与共建平台——人人可浏览、可参与共创，Web 端负责建造与管理，手机端负责发现与阅读。

### 1.3 产品愿景

让任何人都能创建、Fork、参与一个世界观社区；每个世界观拥有自己的 Wiki 式主页以沉淀设定，通过共创积累作品，通过写作工具连接设定与故事，最终形成可持续生长的 fictional universe 生态。

**重要澄清**：Wiki **不是**「无限企划」平台级的总百科，而是 **每一个世界观各自的主页形态**——有多少个世界观，就有多少套互相独立的 Wiki。

### 1.4 核心能力

| 能力 | 说明 | 优先级 |
|------|------|--------|
| **浏览** | 发现世界观、阅读作品与该世界的 Wiki 主页 | P0 |
| **共创** | 投稿剧情、小说、美术等素材 | P0 |
| **世界观 Wiki 主页** | 每个世界自己的设定主页（介绍、词条、时间轴、发展史） | P0 |
| **写作** | 绑定某一世界观、自动链接该世界词条、反哺该世界 Wiki | P1 |
| **权限** | 创建者配置审核/开放策略 | P0 |
| **Fork** | 基于已有世界观派生分支 | P1 |
| **聊天/讨论** | 社区内交流（形式待定） | P2 |
| **商业化** | 订阅、打赏、数字作品等（远期） | P3 |

### 1.5 设计原则

1. **世界观优先**：所有内容必须归属某一世界观，不做泛内容流。
2. **Web 创作、手机阅读**：复杂编辑与管理放在 Web；手机专注体验与发现。
3. **渐进开放**：先支持创建者主导 + 审核制共创，再逐步放开「人人可编辑」。
4. **设定与作品联动**：Wiki 词条与共创作品、写作内容互相引用，形成闭环。
5. **创建者自治**：每个世界观的协作规则由创建者配置，平台提供能力而非统一管制。

## 2. 目标用户与角色

### 2.1 目标用户

- OC / 原创设定爱好者
- 小说、剧本、图文创作者
- 跑团（TRPG）主持与玩家
- 语 C、同人、世界观爱好者
- 独立世界观 IP 的创建者与共建者

### 2.2 平台内角色

| 角色 | 说明 | 典型行为 |
|------|------|----------|
| **访客** | 未登录用户 | 浏览公开世界观、公开作品与 Wiki |
| **浏览者** | 已登录，以阅读为主 | 关注世界观、收藏作品、评论（可选） |
| **贡献者** | 参与某一世界观共建 | 投稿作品、提交 Wiki 草稿、参与讨论 |
| **编辑** | 被授权的成员 | 直接编辑 Wiki、审核投稿 |
| **创建者** | 世界观所有者 | 创建世界、设计主页、配置权限、管理成员 |
| **Fork 作者** | 派生世界创建者 | Fork 世界观、维护分支、标注与原作关系 |

同一用户在不同世界观下可以拥有不同角色。

## 4. 信息架构

### 4.1 Web 端页面结构

```
Web
├── 广场（平台级首页 · 以浏览作品为主）
│   ├── 【登录后】最新作品流（置顶：先看作品；标明作品名与所属世界观）
│   └── 世界观发现区（次要：想找世界时再往下看）
├── 某一世界观
│   ├── 入口页（欢迎词 + 该世界最新作品）
│   ├── 该世界的 Wiki 式主页（介绍 / 词条 / 时间轴 / 发展史）
│   ├── 共创区
│   └── 讨论区（后续）
├── 写作界面（须先选择世界观）
├── 用户控制台
│   ├── 我的世界观
│   ├── 创建世界观
│   ├── Fork 世界观
│   ├── 该世界主页设计器（欢迎词、Wiki 结构与展示）
│   ├── 权限与成员管理
│   ├── 投稿审核队列
│   └── 账户设置
└── 登录 / 注册
```

> 广场的第一件事是 **浏览作品**，不是浏览世界观列表。作品会带来自哪个世界的标注；Wiki 仍只属于某一个世界观。

### 4.2 手机端页面结构

```
App
├── 广场（首页 · 以浏览作品为主）
│   ├── 【登录后】最新作品流（作品名 + 所属世界观）
│   └── 世界观发现区（次要）
├── 某一世界观 · 入口页
│   ├── 创建者欢迎词
│   ├── 该世界最新作品流
│   └── 进入该世界 Wiki 主页
├── 某一世界观 · Wiki 式主页
│   ├── 世界介绍
│   ├── 词条列表 / 词条详情
│   ├── 时间轴
│   └── 发展史
├── 作品详情（小说 / 素材等）
└── 我的（账户、收藏等，后续）
```

### 4.3 世界观内部结构

每个「世界观」是一个独立社区容器；**其主页采用 Wiki 样式**，内容只属于该世界：

```
世界观 (World)  ← 独立容器，自有一套 Wiki
├── 元信息（名称、封面、简介、标签、创建者、Fork 来源）
├── 入口 / 主页配置（欢迎词、布局、主题样式）
├── 权限策略
├── 该世界的 Wiki 式主页
│   ├── 世界介绍（该世界 Wiki 首页）
│   ├── 词条（人物 / 地点 / 物品 / 组织 / 事件 …）
│   ├── 时间轴
│   └── 发展史
├── 共创内容（作品流）
│   ├── 小说 / 章节
│   ├── 剧情片段
│   ├── 美术 / 插画
│   └── 其他素材
├── 成员与角色
└── Fork 分支列表
```

## 5. 功能详述

### 5.1 广场（平台首页）

**目的**：让用户 **先浏览作品**，而不是一上来就面对世界观列表。  
作品自然来自各个世界观；每条作品标明名称与所属世界，感兴趣再点进那个世界。

#### 5.1.1 登录后的广场（主形态）

登录后，广场自上而下为：

1. **最新作品流（主内容 · 置顶）**  
   - 用户在这里 **阅读/发现作品**（小说、剧情、美术等）  
   - 作品来自平台上各个世界观，但交互心智是「看作品」，不是「逛世界目录」  
   - 每条至少展示：  
     - **作品名称**  
     - **所属世界观**（可点进该世界入口页）  
     - 建议同时展示：作品类型、作者、更新时间（可选缩略图）  
   - 点击作品名 → 作品详情  
   - 点击世界观名 → 该世界入口页  

2. **世界观发现区（次要 · 在下方）**  
   - 世界观卡片：封面、名称、简介、标签等  
   - 给「已经想找某个世界 / 想建世界」的人用，**不是**登录后的第一视线

```
┌─────────────────────────────────────────┐
│  最新作品（先看这些）                      │
│  · 《离港通知书》  · 银轨纪元              │
│  · 《雨夜档案》    · 雾港编年              │
│  · 《沙海停战》插画 · 赤砂王朝             │
├─────────────────────────────────────────┤
│  发现世界观（需要时再往下看）               │
└─────────────────────────────────────────┘
```

#### 5.1.2 未登录 / 访客

- 同样以作品浏览为主（公开作品只读）  
- 可用简短品牌介绍；登录后不必用大 Hero 抢作品流的位置

#### 5.1.3 与「世界入口页作品流」的区别

| | 广场 · 最新作品 | 某世界入口页 · 最新作品 |
|--|----------------|------------------------|
| 用户在做什么 | **浏览作品**（作品来自各世界） | 已进入某世界后，看**该世界**更新 |
| 展示重点 | 作品名 + 它属于哪个世界 | 该世界内的更新目录 |
| 世界观列表 | 放在下方，次要 | 不需要（已在世界内） |

**设计原则**：不要把「选世界观」当成进站第一关；作品是钩子，世界是容器。

**Web 与手机**：结构一致，UI 各自适配。

### 5.2 用户控制台（Web）

每位注册用户拥有个人控制台。

#### 5.2.1 创建世界观

- 填写基础信息：名称、简介、封面、标签
- 设置可见性：公开 / 私密（私密仅邀请可见，可后续实现）
- 初始化 Wiki 结构：世界介绍页、默认词条分类
- 撰写欢迎词
- 配置默认权限策略

#### 5.2.2 Fork 世界观

- 基于已有**公开**世界观创建派生分支
- 保留与原作的关系链接（原作世界观、Fork 时间点）
- Fork 时可选择：
  - **全量复制**：复制当前 Wiki 快照与结构（不复制他人作品，或仅复制结构）
  - **空白 Fork**：仅继承元信息与归属关系，内容从零开始（可选策略）
- Fork 作者成为新世界的创建者，拥有独立权限配置

**Fork 规则（建议）**：

| 项目 | 规则 |
|------|------|
| 署名 | 派生世界必须展示原作链接 |
| 作品 | 默认不复制原作共创作品，仅复制 Wiki 结构/快照（具体策略可配置） |
| 同步 | 原作更新不自动同步到 Fork；Fork 独立演化 |
| 商业化 | 若涉及付费，Fork 世界的收益分配规则待远期定义 |

#### 5.2.3 设计世界观主页

- 编辑欢迎词 / 世界介绍（Markdown）
- **Wiki 样式由创建者配置，平台负责渲染**（不开放任意 HTML/CSS）
- 可配置项写入 `worlds.homepage_config`：
  - 主题：`paper` / `ink` / `mist` / `ember`
  - 布局：`classic`（单栏）/ `sidebar`（左侧目录）/ `magazine`（双栏）
  - 头图：`banner` / `compact` / `none`
  - 模块开关与顺序：介绍 / 人物 / 物品 / 时间轴
  - 可选强调色（`#RRGGBB`）、是否显示 tags
- 入口页展示模块（最新作品等）可后续扩展同一配置对象

#### 5.2.4 权限与成员管理

创建者可配置：

**内容投稿**
- 开放投稿：成员投稿后直接公开
- 审核投稿：需创建者/编辑审核通过后公开
- 仅邀请：仅指定成员可投稿

**Wiki 编辑**
- 仅创建者
- 创建者 + 编辑
- 所有成员可编辑
- 成员仅可提交草稿，由编辑合并

**其他权限（后续细化）**
- 邀请成员 / 移除成员
- 任命编辑
- 管理 Fork 策略（是否允许被 Fork）
- 删除作品 / 回滚 Wiki 版本

### 5.3 世界观入口页

用户进入某一世界观后，**首先看到入口页**（欢迎与动态），再按需进入该世界的 Wiki 式主页。

入口页 **不属于** 平台百科，只是该世界的「落地扉页」。

**模块**：
1. **创建者欢迎词**：创建者撰写的引导性文字，介绍世界、入坑指南、社区规则等
2. **最新作品流**：该世界观下按时间倒序的内容更新

**作品类型**（可扩展）：

| 类型 | 说明 |
|------|------|
| `novel` | 小说 / 长篇 |
| `chapter` | 章节（归属某小说） |
| `story` | 独立剧情片段 |
| `artwork` | 美术 / 插画 |
| `audio` | 音频 |
| `video` | 视频 |
| `other` | 其他素材 |

**交互**：
- 点击作品 → 作品详情
- 点击「进入主页 / Wiki」→ 进入 **该世界观自己的** Wiki 式主页

Web 与手机端内容与数据源一致，手机端首版以阅读为主。

---

### 5.4 世界观的 Wiki 式主页

> **范围**：每个世界观各自一份；形态类似游戏 Wiki / 设定集网站，由该世界的创建者与成员共同维护。  
> **不是**：无限企划全站共用的一个大 Wiki。

「银轨纪元」有银轨的 Wiki 主页，「雾港编年」有雾港的 Wiki 主页——彼此词条、时间轴、权限均隔离。

#### 5.4.1 模块

| 模块 | 说明 |
|------|------|
| **世界介绍** | 该世界 Wiki 的首页，概述背景、核心设定、阅读引导 |
| **词条** | 人物、地点、物品、组织、事件等可链接条目（仅本世界内） |
| **时间轴** | 按时间排列的重要事件，可关联本世界词条 |
| **发展史** | 该世界观演变记录：重大版本、剧情节点、社区里程碑 |

#### 5.4.2 词条

- 每个词条有：标题、分类、正文（富文本/Markdown）、别名（用于链接消歧）、关联词条、创建者/最后编辑者
- 词条之间可互相链接
- 支持版本历史与回滚（P1，架构预留）

#### 5.4.3 编辑流程

根据权限策略：

```
成员撰写 → [直接发布 | 提交草稿] → [编辑审核] → 公开
```

---

### 5.5 共创界面（Web）

在某一世界观之下，成员可投稿并共享内容。

**流程**：
1. 选择世界观
2. 选择内容类型（小说、剧情、美术等）
3. 填写标题、正文/上传文件、关联词条（可选）
4. 提交 → 按权限直接发布或进入审核队列

**内容要求**：
- 必须归属某一世界观
- 可关联零个或多个 Wiki 词条
- 支持标签（后续）

**审核队列（Web 控制台）**：
- 创建者/编辑可批准、驳回、要求修改
- 驳回需填写原因（可选）

---

### 5.6 写作界面（Web）

专用写作环境，强化「故事与设定联动」。

**能力**：
1. **选择世界观**：写作绑定到特定世界观上下文
2. **词条自动链接**：输入 `[[词条名]]` 或使用 `@` 触发补全，自动关联 Wiki 词条
3. **消歧**：同名词条弹出选择列表
4. **贡献词条**：写作过程中可快速新建或补充词条（按 Wiki 权限）
5. **发布**：保存为草稿 / 发布为作品 / 导出（后续）

**链接规则**：
- 链接指向该世界观下的词条
- 词条被删除或改名时，链接状态标记为失效，支持手动修复（后续）

---

### 5.7 聊天 / 讨论（后续，P2）

形式待定，候选方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 作品/词条评论 | 实现简单，上下文清晰 | 缺少社区感 |
| 世界观讨论区（帖子） | 适合脑暴、问答 | 与 Wiki 分离 |
| 频道式聊天 | 实时、有氛围 | 成本高、难沉淀 |

**建议**：首版不做独立聊天；P2 先做「作品评论 + Wiki 词条讨论」，再视需求加讨论区。


## 7. 内容模型

### 7.1 核心实体关系

```
User ──创建──▶ World
User ──投稿──▶ Work
User ──编辑──▶ WikiEntry
World ──包含──▶ WikiEntry
World ──包含──▶ Work
World ──包含──▶ TimelineEvent
World ──Fork自──▶ World (parent)
Work ──关联──▶ WikiEntry (多对多)
WikiEntry ──链接──▶ WikiEntry (多对多)
User ──拥有角色──▶ WorldMember (在某 World 下)
```

### 7.2 内容类型枚举

**作品 (Work)**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| world_id | UUID | 所属世界观 |

## 9. 技术架构（概要）

> 本节为架构方向，具体选型在开发前确认。

### 9.1 整体架构

```
┌─────────────┐     ┌─────────────┐
│  Web 前端   │     │ HarmonyOS   │
│  (待定)     │     │ App (ArkTS) │
└──────┬──────┘     └──────┬──────┘
       │                   │
       └─────────┬─────────┘
                 │ REST / GraphQL API
         ┌───────▼───────┐
         │   后端服务    │
         │   (待定)      │
         └───────┬───────┘
                 │
         ┌───────▼───────┐
         │   数据库      │
         │   (待定)      │
         └───────────────┘
```

### 9.2 原则

- **API 优先**：Web 与 App 共用同一套后端 API
- **世界观为边界**：数据隔离、权限校验均以 `world_id` 为上下文
- **手机端只读起步**：App 首版仅调用读接口 + 账户相关接口

### 9.3 当前仓库

- 本仓库现仅有 **HarmonyOS App 工程骨架**（`entry` 模块，默认 Hello World）
- Web 端与后端尚未创建，开发时需新建项目或扩充 monorepo 结构

## 11. 后续发展 · 贡献生态与商业化

### 11.1 贡献生态

世界观越成熟，可承载的内容类型越多：

- 设定库：词条、时间轴、关系图
- 创作层：小说、剧本、漫画、插画、音乐
- 扩展层：跑团模组、设定集导出、世界地图（远期）

所有贡献仍归属世界观容器，形成 **「世界资产库」**。

### 11.2 商业化方向（远期，非 MVP）

| 模式 | 说明 |
|------|------|
| 订阅 | 付费访问完整 Wiki、独家章节 |
| 打赏 | 对作品、世界观、作者打赏 |
| 数字售卖 | 设定集、插画集、小说章节 |
| 平台增值 | 高级控制台、存储、数据分析 |
| IP 延伸 | 授权、周边、改编（最远期） |

### 11.3 前提条件

- 清晰的 **署名与版权** 规则（投稿协议）
- 开放共创与付费内容的 **分区策略**
- Fork 世界的 **收益与署名** 规则
- 贡献记录可追溯（谁创建、谁编辑、何时）

## 13. 名词表

| 名词 | 说明 |
|------|------|
| 世界观 (World) | 平台核心容器；每个世界自带 Wiki 式主页、作品、成员、权限 |
| 入口页 | 进入某世界观后的首屏落地页：欢迎词 + 最新作品 |
| Wiki 式主页 | **该世界观自己的**设定主页（介绍、词条、时间轴、发展史），非平台总百科 |
| 词条 (Entry) | 某世界 Wiki 内的单条设定，如人物、地点、物品；不可跨世界混用 |
| 作品 (Work) | 归属某世界观的共创内容，含小说、剧情、美术等 |
| 共创 | 成员向某一世界观投稿、编辑该世界 Wiki 的行为 |
| Fork | 基于已有世界观创建派生分支（新世界拥有自己的 Wiki） |
| 创建者 | 某一世界观的所有者，拥有该世界最高管理权限 |
| 广场 | 平台首页：以浏览作品为主（作品名+所属世界）；世界观列表在下方、次要 |
| 作品优先 | 进站先看作品，而不是先选/先逛世界观；世界是作品背后的容器 |
